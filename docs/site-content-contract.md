# Контракт публичных поверхностей `pismenny_site`

`publication_target: pismenny_site` охватывает главную страницу, навигацию, карточки, подборки и самостоятельные публичные страницы `pismenny.ru`, кроме полного лонгрида в `/articles/`. Полные статьи принадлежат цели `pismenny_blog` и собираются по [`docs/article-creation-checklist.md`](article-creation-checklist.md).

## Граница между сайтом и блогом

Для обычной статьи сайт использует `variant_kind: article_card`, `collection_entry` или `navigation_link` и ведёт на `public_canonical_url` из publication record. Карточка может сокращать заголовок и описание, но не должна становиться второй копией полного текста.

Самостоятельная страница с полным содержанием статьи создаётся только после явного решения:

1. зафиксировать отдельный publication item для `pismenny_site`;
2. выбрать в publication record единственный `public_canonical_url`;
3. на неканонической копии указать этот URL через `<link rel="canonical">`;
4. определить, зачем читателю нужны обе поверхности.

Так сайт может продвигать статью, не конкурируя с блогом за публичную идентичность материала.

## Виды представлений

| `variant_kind` | Назначение | Самостоятельный URL |
|---|---|---|
| `article_card` | Короткий анонс статьи в карточке | Нет; ссылка ведёт на статью |
| `collection_entry` | Элемент тематической подборки или архива | Обычно нет |
| `navigation_link` | Навигационная ссылка без самостоятельного текста | Нет |
| `standalone_page` | Отдельная публичная страница сайта, не являющаяся обычным блоговым лонгридом | Да |

Новый повторяемый вид добавляется в контракт только после появления реального компонента. Разовая композиция страницы не требует нового глобального enum.

## Источники данных

- Смысл статьи, `article_type`, `article_section` и основания знания приходят из source article в `my-os`.
- `public_canonical_url` и фактический `publication_status` читаются из publication record.
- Проектные формулировки и контакты приходят из документа конкретного проекта; этот контракт не становится владельцем публичного текста.
- Визуальный стиль приходит из `pismenny-editorial-systems`, а размеры и кадрирование задаёт реальный компонент сайта.

Карточка статьи содержит как минимум понятный заголовок, короткое описание, рабочую ссылку и, если используется изображение, содержательный `alt`. Видимые тип и рубрика должны совпадать с source article; не использовать тематическую рубрику как замену редакционному типу.

Карточка показывает публичную метку `article_type`, если компонент предусматривает редакционную метку. При `content_basis: author_experience` можно дополнительно показать «Из практики»; остальные основания не становятся обязательными бейджами.

## Статус и обнаружение

Значения `publication_status` определяет [`my-os/content/publications/README.md`](/Users/danil/code/my-os/content/publications/README.md). Для `pismenny_site` применяется следующая проекция:

- `not_started` и `planned` — публичное представление отсутствует;
- `draft` и `review` — элемент не включается в публичную навигацию; если самостоятельная страница доступна по прямой ссылке, она получает `noindex,nofollow,noarchive` и видимую пометку черновика;
- `published` — карточка или ссылка видима, а самостоятельная страница может индексироваться и добавляется в sitemap;
- `retired` — элемент удаляется из навигации и sitemap; самостоятельный URL перенаправляется на преемника, если статическая инфраструктура поддерживает корректный redirect, либо сохраняется как явно архивный `noindex`-материал.

Каждое самостоятельное представление, которое нужно отслеживать отдельно, получает собственный `publication_id` в record. Несколько карточек одного и того же вида не требуют отдельных publication items, если они являются одной и той же проекцией данных в разных списках.

Для встроенной карточки или ссылки publication record хранит URL содержащей страницы, по возможности со стабильным anchor компонента. Если стабильного адреса у компонента нет, в URL ставится `—`, но artifact обязан точно указывать файл и идентификатор элемента, например `index.html#article-agent-meaning`.

## Проверка

- [ ] Представление не дублирует полный блоговый лонгрид без зафиксированного решения.
- [ ] Ссылка ведёт на `public_canonical_url` из record.
- [ ] В publication record указан собственный URL, URL содержащей страницы с anchor либо точный artifact locator.
- [ ] Заголовок, описание, тип и рубрика не противоречат source article.
- [ ] Статус элемента согласован с навигацией, индексированием и sitemap.
- [ ] Самостоятельная страница имеет уникальные title, description и canonical.
- [ ] Изображение не растянуто, а `alt` описывает его смысл.
- [ ] Публичная доставка проверена по [`docs/deployment.md`](deployment.md).
